v11 performance-core candidate (2026-10-12)
------------------------------------------
The tester reports no effect from hints and headroom separately or in their
on/off combinations. No conclusion about Samsung accepting clock requests
is drawn from API success. ARMSX2 2.6.7 documents big/prime group affinity
as its default, while ADPF was introduced off by default in 2.6.5. Source
inspection at 6cfb3070664ceeb3c0efdcc8aa5362ed3a090c64 confirms group
placement. Our port previously set no Android core affinity.

v11 adds optional Use performance CPU cores (default off). Before native
hint-session setup, the current frame producer and optional GL worker can
restrict themselves to a group within their current allowed CPU masks.
Complete cpu_capacity metadata is preferred, then complete cpuinfo_max_freq
metadata; scales are not mixed. Cores at least 75% of the peak ranking are
selected, only if that identifies a distinct group with at least two cores.
Missing metadata, a homogeneous/already-narrow mask or a lone prime leaves
placement unchanged. Rejected affinity calls also fall back. No individual
core numbers are hard-coded, clock speed is not forced, and no helper work
is manufactured to raise clocks. Each participating thread attempts once
per game process and logs requested/effective masks or a fallback reason.
The option works with ADPF disabled. Existing headroom/display options
remain opt-in. Version preview.11 / Android version code 15711.

Do not run the Android container/emulator for this follow-up. Validate the
host topology-selection/controller tests, launcher checks, Android builds,

v12 background pacing fix (2026-10-12)
--------------------------------------
The tester confirmed v11 applied CPUs 2–7 but performance cores alone did
not help. Hints/headroom combinations also had no effect. Their all-options-
off timing log shows roughly 11–13 ms average frame work, 0.5–0.6 ms swaps,
and frequent 33–35 ms frames with 29–66 background yields per 120 frames.
CPU frequency samples reach 3.15 GHz, so low clocks alone do not account
for these drops. Separate log windows are not perfectly aligned; do not
infer an exact per-frame correlation from adjacent summary lines.

The old background fallback waited for another VI retrace whenever a frame
was already due and a lower-priority SDK worker was runnable. v12 instead
temporarily blocks the frame producer for a cooperative worker turn. It
returns as soon as workers block/exit or after a 1 ms budget at an SDK
scheduling checkpoint. Uninterrupted native work can exceed that budget.
Normal frame targets, SDK priorities and optional performance settings are
preserved. Background average/max time is added to existing pacing logs.
Android version preview.12 / version code 15712.

Host regression tests run the actual Android-configured scheduler and VI
frame-wait code without a ROM, GPU or VI timer. They cover short jobs,
continuously runnable yield/poll jobs, higher-priority work, IRQ-state and
scheduler guards, worker exit and repeated handoffs. An already-due frame
returns without a new retrace, retaining background progress. Existing
fallback code stalls in that same no-timer regression fixture. Existing
32/64-bit frame-rate checks pass. Android builds and APK packaging are
validated separately; no Android container/emulator runtime test is run.

Device comparison: keep 60 FPS, scale 1, performance hints, headroom,
display matching and performance CPU cores OFF; Log performance timings
ON. Skip movies for steady gameplay comparison. Use the same stationary
